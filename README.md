# Точка сборки — портфолио независимой команды

Русскоязычный сайт на Next.js App Router, React и TypeScript. Тёмная адаптивная тема, собственные иллюстрации, CSS-анимации с поддержкой уменьшения движения, фильтры проектов, мобильное меню, отдельные страницы кейсов. Tailwind CSS подключён; основная дизайн-система находится в `src/app/globals.css`. Шрифт Manrope хранится локально через npm, запросов к Google Fonts при сборке нет.

## Запуск

Нужен Node.js 22 или новее и npm. Рекомендуется Node.js 24 LTS.

```bash
npm ci
npm run dev
```

Откройте адрес, который выведет Next.js (обычно порт 3000). Сервер доступен на сетевых интерфейсах для облачной разработки.

## Где менять содержимое

| Что изменить                                    | Файл                                                     |
| ----------------------------------------------- | -------------------------------------------------------- |
| Название команды, заголовок, описание, контакты | `src/content/site.ts`, объект `site`                     |
| Имя руководителя                                | `src/content/site.ts`, `site.contacts.managerName`       |
| Участники команды                               | `src/content/site.ts`, массив `team`                     |
| Услуги, этапы и преимущества                    | `src/content/site.ts`, `services`, `process`, `benefits` |
| Проекты, статусы, описания и изображения        | `src/content/projects.ts`, массив `projects`             |
| Цвета, размеры и адаптивная сетка               | `src/app/globals.css`                                    |

Работайте с текстом внутри кавычек; сохраняйте запятые и фигурные скобки. TypeScript поможет заметить пропущенное обязательное поле. После правок запустите `npm run typecheck` и `npm run build`.

### Контакты

В `site.contacts` замените `null` на значения в кавычках:

```ts
telegram: "https://t.me/ваш_логин",
email: "ваш@домен.ru",
managerName: "Ваше имя",
```

Укажите настоящий Telegram-логин (латиница, цифры и подчёркивание, не короче 5 знаков) и реальный email. Пока оба значения отсутствуют или некорректны, сайт честно показывает, что контакты не добавлены. Форма заявок не реализована: сервер отправки, сторонняя почтовая интеграция и сбор персональных данных не требуются. По email открывается почтовая программа, Telegram ведёт во внешний сервис.

### Новый кейс

1. Откройте `src/content/projects.ts`.
2. Скопируйте один объект внутри `projects` и измените `slug` на уникальный адрес латиницей, например `new-service`.
3. Заполните название, описание, ссылку, задачу и вклад команды. `status: "commercial"` используйте только для подтверждённой коммерческой работы, иначе `"demo"`.
4. В `features` перечисляйте только подтверждённые функции. Неизвестные технологии оставьте `[]`, сроки и бюджет — `null`.
5. `visual` выбирает авторскую обложку: `"creators"`, `"auto"` или `"crm"`. Это иллюстрации, а не скриншоты.
6. Добавьте разрешённые к публикации снимки в `images` (см. ниже).

Карточка, страница `/projects/ваш-slug`, последовательность кейсов и sitemap обновляются из массива автоматически.

### Скриншоты и фотографии

Сейчас используются типографические аватары и авторские иллюстрации без сторонних логотипов. Для галереи положите разрешённые снимки в `public/projects/название/`, желательно WebP или AVIF, и добавьте в `images`:

```ts
images: [
  { src: "/projects/название/main.webp", alt: "Главная страница проекта на компьютере", width: 1600, height: 1000 },
],
```

Укажите реальные размеры изображения. Первый снимок автоматически становится обложкой карточки и страницы кейса; все снимки появляются в галерее. Менять компоненты для этого не нужно. Next Image создаёт оптимизированные варианты. Используйте локальные файлы: внешние домены изображений намеренно не разрешены. Пока `images: []`, показываются авторская иллюстрация и честное сообщение об отсутствии снимков.

## Проверка и production

```bash
npm run lint
npm run typecheck
npm run build
npm run start
```

Браузерные проверки выполняются **после сборки**, поскольку тестовый сервер использует production-режим:

```bash
npm run build
npm run test:e2e
```

В облачной среде используется Chromium `/usr/bin/chromium`. На своей машине установите Chromium через Playwright:

```bash
npx playwright install chromium
PLAYWRIGHT_CHROMIUM_EXECUTABLE="$(node -e 'console.log(require("playwright").chromium.executablePath())')" npm run test:e2e
```

В Windows задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE` средствами своей оболочки. Тесты проверяют маршруты, фильтры, аккордеон, мобильное меню и возврат фокуса, отсутствие горизонтального скролла на 4 ширинах, уменьшение анимаций, SEO-ресурсы и 404. Тестовые подписи главного заголовка нужно обновлять при изменении текста.

## Развёртывание на Vercel

Публичный деплой не выполнялся. Чтобы опубликовать сайт:

1. Сохраните проект в своём GitHub-репозитории.
2. В Vercel выберите **Add New → Project**, подключите репозиторий. Framework Preset — **Next.js**.
3. Если репозиторий содержит только этот проект, Root Directory оставьте корнем, Build Command — `npm run build`. Выберите Node.js 24.x.
4. Добавьте переменную `NEXT_PUBLIC_SITE_URL` с полным реальным HTTPS-адресом сайта без пути. Например, адрес вашего Vercel-проекта или подключённого домена. Это публичный адрес, не секрет.
5. Запустите Deploy по своему решению. После подключения собственного домена обновите переменную и пересоберите сайт.

Для локальной настройки скопируйте `.env.example` в `.env.local`. `.env.local` не попадает в Git. На Vercel также автоматически используется `VERCEL_PROJECT_PRODUCTION_URL`. Без обоих адресов сайт собирается и работает, но sitemap пустой, а абсолютные canonical-адреса не выставляются: выдуманного домена в проекте нет. При настроенном адресе sitemap включает главную и все кейсы. OG-изображение генерируется локально по адресу `/opengraph-image`; метаданные, robots и favicon включены.

## Перед публикацией необходимо

- Указать настоящее имя руководителя, Telegram и/или email.
- Подтвердить или изменить рабочее название «Точка сборки».
- Изучить реальные страницы трёх проектов: из облачной среды доступ к ним был закрыт сетевой политикой (HTTP 403 на уровне прокси).
- Для «Творцов» подтвердить назначение платформы, публичные функции и конкретные модули Вовика. Факт его привлечения к коммерческой разработке взят из задания владельца.
- Проверить фактические возможности обоих демопроектов. Не приписывать им коммерческое внедрение.
- Добавить скриншоты с разрешением на публикацию. Авторские иллюстрации сейчас прямо отмечены как иллюстрации.
- При желании добавить подтверждённые технологии, сроки и бюджет; пустые поля не отображаются.
- Указать production-адрес и проверить внешние ссылки из обычного браузера.

Никаких придуманных отзывов, заказчиков, реквизитов и метрик нет. База данных, CMS, аналитика и серверная отправка заявок не подключены. Если позднее добавите форму, понадобятся реальный серверный обработчик, серверная валидация, защита от спама, согласие и подходящая политика обработки персональных данных.
